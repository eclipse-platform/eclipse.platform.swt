# Tree coordinates hidden by collapsed ancestors

## Result and scope

A qualified canonical Maven/OpenRewrite recipe corrects one active common Tree projection defect on SWT master `678da68f34007af0aab0689aa72bd85fb44b800e`. Valid child coordinates now return `-1` while their parent, or any ancestor, is collapsed. A visible parent still uses exact long row arithmetic. The public API, parent-owned topology, exposed `TreeItem` identities and normal collapse-selection behavior are preserved.

The native regression uses the explicit GTK3 logical model (`org.eclipse.swt.internal.gtk.virtualTreeLogicalNativeModel=true`). This evidence does not promote that model to the default, qualify GTK4/Win32/Cocoa, or establish complete viewport resource/screenshot acceptance.

## Failure reproduced before correction

`visibleIndexOfCoordinate(parentId, childIndex)` previously computed `visibleIndexOf(parentId) + 1` without checking whether the children were visible. A hidden parent at row `-1` became a nonnegative child coordinate; a visible collapsed parent also returned a row for its hidden child.

The real GTK accessibility adapter calls this method for selected logical coordinates. The native test expands a nested branch, selects a leaf and a root sibling, collapses the branch, then uses public `Tree.select(leaf)` to select the hidden leaf without revealing it. The old adapter returns two selected rows while its selected-row count is one. The fix reports only the visible root sibling. The test also collapses an ancestor while the branch remains marked expanded and restores expansion afterward.

The existing collapse behavior clears descendant selection. The test asserts that behavior before explicitly selecting the hidden item; it does not change collapse or `setSelection` semantics.

## Changes generated by the recipe

- Add a collapsed-parent check and hidden-parent check in `VirtualTreeVisibleProjection.visibleIndexOfCoordinate`, with exact addition for the visible parent row.
- Add three headless regression tests covering immediate and ancestor collapse, coordinates beyond the signed-int row range, invalid coordinates, facade nonmaterialization, and 32 seeded trees with 32 expansion changes per seed checked against an independent eager preorder oracle.
- Add one actual GTK3 Tree/accessibility test covering row-list/count consistency, selected-item identity, expansion restoration, zero programmatic `Selection` events and 100 repeated hidden-coordinate queries without additional `SetData` events.
- Register both classes in `AllWidgetTests`.
- Correct one existing `Test_VirtualTreeWindow` assertion to expect a `long`: the reflected method returns `Long`, while the former `Math.max(0, ...)` expectation boxed `Integer`. The preexisting false failure is retained in `swt-existing-overscan-baseline-type-failure-20261017.log`.

## Reproduction

Use Java 21, JUnit Platform Console with the Jupiter and Vintage engines, GTK3 development libraries and an X11 display (Xvfb works). Build native sources through the repository's supported collector:

```sh
cd bundles/org.eclipse.swt
java -Dws=gtk build-scripts/CollectSources.java -nativeSources /tmp/swt-coordinate-native
SWT_JAVA_HOME=/path/to/jdk-21 GTK_VERSION=3.0 MAKEFLAGS=-j4 bash /tmp/swt-coordinate-native/build.sh -gtk3
```

Compile the 546 GTK Java source files from the repository root using `javac --release 21 -encoding UTF-8 -d /tmp/swt-coordinate-classes @docs/verification/tree-coordinate-visibility-20261017/gtk-source-files.args`. The JSON receipt lists the complete test compiler and runner arguments. Replace the recorded checkout/toolchain/output paths with local equivalents. Copy `SWTMessages.properties` and the GTK CSS resources into the compiled class tree, as the normal bundle build does. Run the native class with `-Djava.library.path=/tmp/swt-coordinate-native`, `-ea`, `-Xmx512m` and `SWT_GTK3=1` under the X11 display.
